# DEV-01C — Diagnóstico de runtime de la experiencia UI

## Objetivo
Determinar con evidencia reproducible por qué la UI observada no coincide con la experiencia servida actualmente, tomando `6caccce` como snapshot de source pre-DEV01C que se debe diagnosticar, y dejar un diagnóstico de runtime verificable sin iniciar sesión ni alterar backend o datos.

## Scope

**Incluye**
- Contrastar la identidad Git conocida, la fuente actual de las rutas y la respuesta del servidor en ejecución; evaluar de forma explícita si existe discrepancia de versión fuente, proceso, puerto o artefactos `.next`.
- Inspeccionar el proceso conocido `next dev` en `:3000`, sus ancestros y cwd, y comparar con un servidor controlado de la rama actual en un puerto libre distinto. No asumir que un listener representa la versión fuente actual sólo por compartir el proyecto. Si hace falta aislar `.next` compartido, se puede detener únicamente un listener confirmado como propio del proyecto, después de registrar PID, proceso/ancestros, cwd, inicio y motivo; no detener servicios ajenos.
- Documentar diagnóstico y evidencia en `docs/ui-redesign/DEV-01C-RUNTIME-AUDIT.md`; capturar pantallas desktop/móvil con viewport y origen/puerto registrados.
- Revisar el historial de UI en `backup/lucem-ui-legacy-20261101` (`bf8c45f`) para explicar la diferencia funcional, sin restaurar ni copiar la implementación en esta fase.
- Recomendar DEV-02 como reimplementación visual informada por Stitch que reutilice los servicios y reglas de dominio verificados.

**Fuera de alcance**
- No implementar ni cambiar UI, código, rutas, pruebas, configuración, documentación distinta del informe de auditoría, dependencias, backend, auth/session, API, Prisma, migraciones, infraestructura o base de datos. Esta entrega de Planner sólo reemplaza `SPEC.md`.
- No realizar login, usar credenciales/secretos del README, fabricar sesión, acceder a datos de negocio autenticados, ni ejecutar operaciones mutantes. No modificar los documentos o assets de diseño.
- No atribuir evidencia histórica a una sesión, navegador o caché concreta sin metadatos/HAR que lo prueben.
- No detener servicios ajenos. El listener confirmado del proyecto puede detenerse sólo si hace falta aislar el `.next` compartido y después de registrar su evidencia de identidad y el motivo; no detenerlo por otras razones.
